# 07. Правила работы с проектом

---

## Продукт

**Банки 0.45 л, не 0.5.** Это не ошибка — на 0.5 л банки сложно найти подрядчика с нужным тиражом и ценой. Не "исправлять" в материалах.

---

## Данные и исследования

**Правило трёх проверок.** Перед фиксацией любого числа в исследовании конкурентов (цена, объём, доля) — проверить по трём источникам. Особенно важно для: цен полки, объёмов рынка, данных о листинге.

**Один источник истины.** В репо должен быть один актуальный файл по каждой теме. Не создавать `_V2`, `_ФИНАЛ`, `_РЕАЛЬНЫЕ_ДАННЫЕ`, `_ОБНОВЛЕНО` в именах файлов. Для версионности есть git diff — он показывает что изменилось и когда.

---

## Файловая структура

**Папку проекта не переименовывать.**
Путь: `/Users/mac/Documents/ЛытракинЪ продукция /` — с опечаткой "ЛытрА" и пробелом в конце. Это сознательно сохранённая ошибка: ссылки из Obsidian Vault привязаны к этому пути, переименование их сломает.

**Шаблон для нового бренда:**
```
research/<brand>/
prompts/<brand>/
design/<brand>/
production/<brand>/
```

**Технолог-данные** (КБЖУ, состав, аллергены, штрих-коды) → строго в `production/fills/tehnolog/`. Не копировать в другие места — риск расхождения версий.

**AI-промпты** → `prompts/<бренд>/`, не разбрасывать по чатам и текстовым заметкам.

---

## Дизайн

**Каждый бренд = отдельный проект в Claude Design.** ФИЛЛС и ЛыткаринЪ пиво — разные визуальные языки, не смешивать в одной сессии.

**Черновики → в `scratch/archive/`.** Финальные PDF не хранить рядом с промежуточными.

**Имена файлов.** Предпочитать латиницу через дефис: `klubnika-arbuz-clean.ai`. Не плодить наборы с похожими именами.

**Тяжёлые исходники (>20 МБ) → Git LFS.** Без LFS репо вырастает до неуправляемого размера. Текущие `.ai` файлы (29–44 МБ) должны быть в LFS.

---

## Ассеты

**Один файл = одно место.** Не дублировать ассеты в разных папках. Если нужен файл в двух местах — использовать симлинк или ссылку в документации, но не копию.

**Файлы корня не двигать без проверки.** `.webp` иконки и `logo_lytkarin.png` подключены в `index.html`. Перед сдвигом — искать все вхождения имени файла в `index.html`.

## Шеринг и коммуникация

**Для заказчика = Vercel, не файлы по почте.** Ссылка на `fills-research.vercel.app` — актуальная версия лендинга. Отправлять её, не архивы.

**Сначала бриф, потом работа.** Для крупных задач (новый бренд, новая линейка, редизайн) — написать план и согласовать до начала дизайна или кода.

---

## Коммиты

Conventional commits, кириллица в message OK:

```
feat: добавить SKU малина-мята
fix: исправить цвет фона на мобильных
chore: обновить barcodes для SKU vinograd
docs: добавить профиль бренда BrewPrompt
```

Не скипать хуки (`--no-verify`) без явной причины. Если хук падает — разобраться почему, не обходить.

---

## Антипаттерны

| Что НЕ делать | Почему |
|---|---|
| `_V2`, `_ФИНАЛ` в именах файлов | Нарушает принцип одного источника истины |
| Копировать финальные PDF рядом с черновиками | Путаница, какой идёт в типографию |
| Хранить `.ai` >20 МБ без LFS | Репо пухнет, pull/clone становятся медленными |
| Дублировать ассеты в разных папках | Расхождение версий при обновлении |
| Кириллица с пробелами в именах новых файлов | Ломается в URL, bash-скриптах, CI |
| Переименовывать папку проекта | Сломаются ссылки из Obsidian Vault |
| Двигать .webp из корня без проверки index.html | Лендинг покажет битые ссылки |
